<objective>
Complete the write-gate by swapping the write-path identity from the Phase 1 stub `kya_device_id` to the real Better Auth `user.id`, adding independent defense-in-depth session checks to both write-performing server surfaces (`submitComplaint` Server Action and `POST /api/upload-url` Route Handler), deleting the now-dead `device-id` module, and locking in AUTH-04 with explicit "no redirect" assertions on the public feed/permalink e2e specs.

Per D-03 there is NO device-id → user_id claiming or migration — the module is deleted outright (no fallback, no reconciliation). The `/capture` page gate (Plan 02) stops the UI from rendering, but `submitComplaint` and `/api/upload-url` are independently reachable (replayed request, direct devtools fetch), so each needs its own session check — the route-level gate alone is not sufficient (RESEARCH.md Pitfall 3).

Purpose: Make "gated writes, anonymous browse" true and unbypassable (AUTH-01 write surfaces + AUTH-04 browse).
Output: session-gated submit + upload endpoints, deleted device-id module, updated unit tests, and AUTH-04 e2e assertions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any caller → submitComplaint | A write-performing Server Action reachable by a replayed/forged request independent of the /capture page |
| any caller → POST /api/upload-url | A write-adjacent Route Handler that mints a real R2 presigned PUT URL |
| anonymous browser → /, /c/[id], /api/feed | Public read surfaces that must remain ungated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Elevation of Privilege | submitComplaint + /api/upload-url called directly (gate bypass) | high | mitigate | Each handler independently calls `auth.api.getSession()` and rejects (throw / 401) before any work — defense-in-depth, not reliance on the /capture page gate (Patterns 5, 6; Pitfall 3) |
| T-02-10 | Elevation of Privilege | device-id fallback identity re-entering the write path | high | mitigate | `src/lib/device-id.ts` deleted with zero importers; a `grep` gate confirms no fallback-to-device-id branch exists (RESEARCH.md Anti-Patterns) |
| T-02-11 | Information Disclosure | internal `user.id` exposure (IDOR) | low | accept | `session.user.id` is written only to the server-side `submitter_id` column (already internal-only, never returned in a client payload — same discipline as `complaints.id`); no new client-visible identifier is added this phase |
