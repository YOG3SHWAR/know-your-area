# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scaffolding note:** This project is greenfield — no `package.json`, no Next.js app, no `components.json` exist yet. `shadcn_initialized: false` reflects that `npx shadcn@latest init` has not physically run yet; it is a Phase 1 execution prerequisite (Wave 0), not a research-time step. gsd-executor MUST run shadcn init with the preset below as the first setup task, before building capture/feed components, so every subsequent phase inherits the same tokens.

**Preset to apply during scaffolding:**
```
npx shadcn@latest init
  --style new-york
  --base-color neutral
  --css-variables
```
User confirmed: neutral/slate base, researcher-recommended `new-york` style (cleaner, denser default — reads more "civic utility" than the rounder `default` style, appropriate for a trust-sensitive public reporting tool).

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `style=new-york, baseColor=neutral, cssVariables=true` |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (badge padding, chip gaps) |
| md | 16px | Default element spacing (card padding, form field gaps) |
| lg | 24px | Section padding (page margins on mobile) |
| xl | 32px | Layout gaps (between major page sections) |
| 2xl | 48px | Major section breaks (capture flow step transitions) |
| 3xl | 64px | Page-level spacing (rarely used at mobile widths) |

Exceptions:
- **44px minimum touch target** on the camera shutter/capture button and category-picker chips — overrides the 8-point scale to meet mobile tap-target accessibility minimums (this is a mobile-web-only product per project constraints).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Regular (400) | 1.5 |
| Label | 14px | Regular (400) | 1.5 |
| Heading | 20px | Semibold (600) | 1.2 |
| Display | 28px | Semibold (600) | 1.2 |

- **Body (16px/400):** feed card meta text run-in, permission-denied guidance copy, general paragraph text.
- **Label (14px/400):** distance ("2.3 km away"), relative timestamp ("5m ago"), poster label ("Reported by a nearby resident"), category badge text, form field labels, complaint ID (rendered in Geist Mono at this size).
- **Heading (20px/600):** capture page step titles, permalink page category title, section headers.
- **Display (28px/600):** page-level headline (e.g. feed page top-of-page context, empty-state heading).

Only 4 sizes and 2 weights are declared — no other size/weight combination is permitted in this phase's UI.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (neutral-50) | Page background, capture screen background, permalink page background |
| Secondary (30%) | `#F4F4F5` (neutral-100) | Feed card surfaces, search bar background, category picker chip (unselected) background, top nav bar |
| Accent (10%) | `#F59E0B` (amber-500, "civic amber") | See reserved-for list below — nothing else |
| Destructive/Error | `#EF4444` (red-500) | Permission-denied hard-block screen, inline error/retry states (feed load failure, submit failure, ID-not-found) — no true destructive *actions* (delete/takedown) exist in this phase; this token covers error/blocking states only |

**Accent reserved for:**
- Primary CTA button ("Report a Problem")
- Camera shutter/capture button
- Selected/active category chip (fill + border) in the category picker
- Submit button (final publish action)
- Active/focused state of the search-by-ID input (focus ring only)

No other element (links, icons, nav items, badges) uses the accent color — this keeps amber legible as "this is the primary action" throughout the capture→publish flow.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Report a Problem" |
| Category picker label | "What's the problem?" (helper text above the 5 fixed category chips: Pothole/Road damage, Garbage/Sanitation, Streetlight/Electrical, Water/Drainage, Traffic lights) |
| Capture button | "Capture Photo" (label near shutter button, icon-only shutter itself needs no label) |
| Submit button | "Publish Report" |
| Submit loading state | "Publishing…" (button disabled, spinner replaces label, prevents double-submit) |
| Poster label (feed card + permalink) | "Reported by a nearby resident" (D-06 — no fake usernames) |
| Empty state heading | "No reports near you yet" |
| Empty state body | "Reports from your area will show up here." (Phase 1 minimal placeholder — polished "be the first to report" CTA ships in Phase 6) |
| Feed load error | "Couldn't load reports. Check your connection and try again." + "Retry" button |
| Submit/publish error | "Couldn't publish your report. Check your connection and try again." (form state — photo, category, GPS — is preserved, not cleared) |
| Camera permission denied (hard block) | "Camera access is off. This app only accepts photos taken live in the app, so we can't continue without it. Turn on camera access in your browser's site settings, then reload this page." |
| Location permission denied (hard block) | "Location access is off. Every report needs your live location to show up in the nearby feed, so we can't continue without it. Turn on location access in your browser's site settings, then reload this page." |
| Search-by-ID placeholder | "Enter a report ID (e.g. KYA-7F3X2)" |
| Search-by-ID not found | "We couldn't find a report with that ID. Check the code and try again." |
| Permalink not found (404) | "This report doesn't exist or may have been removed." + "Back to feed" link |
| Distance format | "{X.X} km away" (or "{X} m away" under 1km) — raw distance only, no address until Phase 3 |
| Relative timestamp format | "{N}m ago" / "{N}h ago" / "{N}d ago" |
| Destructive confirmation | Not applicable this phase — no destructive actions exist (delete/report/takedown ship in Phase 5/6) |

## UI Considerations

Applicable state considerations resolved: 15 covered, 4 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Feed (list-collection) | ✅ covered | Renders "No reports near you yet" / "Reports from your area will show up here." per Copywriting Contract |
| loading | Feed (list-collection) | ✅ covered | Initial SSR load shows skeleton feed cards (shadcn `Skeleton`); infinite-scroll pagination shows a small spinner near the sentinel while fetching the next cursor page |
| error | Feed (list-collection) | ✅ covered | Inline error banner "Couldn't load reports…" with Retry button per Copywriting Contract; feed does not blank/crash on query failure |
| populated | Feed (list-collection) | ✅ covered | Single-column mobile scroll of feed cards (photo w/ burned-in overlay, category badge, distance, relative timestamp) — Reddit/Instagram-style per project framing |
| partial | Feed (list-collection) | ✅ covered | If visitor location is denied, feed falls back to recency-only ordering (no distance shown on cards) rather than blocking browsing (D-07) |
| overflow | Feed (list-collection) | ✅ covered | Infinite scroll + cursor pagination handles unbounded item counts (D-09); no fixed-height container to overflow |
| zero-one-many | Feed (list-collection) | ✅ covered | Zero → empty state; one → single card renders with normal spacing (no special-case layout); many → infinite scroll list, same card component |
| empty | Feed card photo (media) | 🧪 backstop | If a photo fails to load (broken R2 URL/CDN issue), render a placeholder tile using the category color + icon instead of a broken-image icon — untested until execution; verify with a forced-404 image URL |
| loading | Feed card photo (media) | ✅ covered | Next.js `<Image>` blur/placeholder while the photo loads |
| loading | Camera capture flow (media/interactive-control) | ✅ covered | "Starting camera…" state (spinner over dark video frame) shown until `getUserMedia` stream is ready |
| error | Camera capture flow (media) | ✅ covered | Camera permission denied → hard-block screen per Copywriting Contract (D-03); no degraded fallback path |
| error | GPS capture (interactive-control) | ✅ covered | Location permission denied → hard-block screen per Copywriting Contract (D-03); no degraded fallback path |
| loading | GPS wait-for-fix (interactive-control) | ✅ covered | Brief "Getting your location…" indicator during the 3-5s wait-for-fix window (D-04); does not block submission past the window |
| long-text | Geotag/timestamp overlay (media) | 🧪 backstop | Overlay text (coords + timestamp burned onto canvas) must wrap or truncate gracefully at narrow photo aspect ratios / very long accuracy strings — untested until real-device capture; verify on a real narrow-aspect phone capture |
| empty | Category picker (form/interactive-control) | ⚪ dismissed | Fixed 5-category list, never empty — no empty-state concept applies |
| long-text | Category picker (form/interactive-control) | ⚪ dismissed | Fixed, short, pre-written category labels — no user-generated text possible |
| loading | Submit action (form) | ✅ covered | "Publishing…" button state (disabled + spinner) per Copywriting Contract, prevents double-submit during upload + insert |
| error | Submit action (form) | ✅ covered | Inline error copy per Copywriting Contract; form state (photo, category, GPS) preserved on failure, not cleared |
| partial | Submit action (form) | ⚪ dismissed | Low-accuracy GPS at submit time is expected behavior per D-04 (submit with best-available accuracy, no blocking threshold), not an incomplete-data error state |
| long-text | Permission-denied block screens (static-content) | ✅ covered | Guidance copy (Copywriting Contract) is short and fits mobile viewports without truncation |
| error | Search-by-ID (form) | ✅ covered | "We couldn't find a report with that ID…" inline under the search box per Copywriting Contract; stays on page, no navigation on failure |
| empty | Search-by-ID (form) | ⚪ dismissed | Single text input, not a collection — no empty-state concept beyond the placeholder copy |
| long-text | Search-by-ID (interactive-control) | ⚠ unresolved | Behavior when pasted input exceeds expected ID length/format (e.g. user pastes a full permalink URL instead of the bare code) is not specified — planner should decide: reject as "not found," or best-effort extract the ID from a pasted `/c/{id}` URL. Flagged as an explicit assumption, not silently dropped. |
| error | Permalink page `/c/{id}` (static-content/media) | ✅ covered | Malformed/nonexistent ID renders a dedicated "This report doesn't exist…" state per Copywriting Contract, not a generic 500/crash |
| loading | Permalink page photo (media) | ✅ covered | Same blur/placeholder pattern as feed card photo loading |
| long-text | Permalink page (static-content) | ⚪ dismissed | No long-form text fields exist on this page in Phase 1 (comments/descriptions ship in Phase 5) |
