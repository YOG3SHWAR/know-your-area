<objective>
Close two capture-surface UAT gaps from real-device testing:

- **G-01-3 (blocker):** On a real device, denying camera or location did NOT show the UI-SPEC hard-block — CameraCapture rendered the raw browser `NotAllowedError` message and PermissionGate failed open (it only hard-blocks when `navigator.permissions.query` proactively reports `denied`, which Safari does not do for `camera` and no browser does on a first-visit `prompt`). Route the actual `getUserMedia()`/geolocation rejection back into PermissionGate's existing hard-block via a shared context, restoring the D-03 contract on every browser.
- **G-01-4 (cosmetic):** The 5-category picker uses `flex flex-wrap` sized to intrinsic label width, so longer labels wrap alone while short ones pair up — an uneven grid. Replace with a fixed 2-column grid so every chip is a uniform cell; keep the 44px (`min-h-11`) touch target.

Purpose: real-device denial must be a dead-end (anti-abuse: live in-app camera is the only submission path, SUBM-01), and the category picker must read as a clean, tappable grid (SUBM-02).
Output: revised PermissionGate + CameraCapture + CategoryPicker, and new e2e coverage that reproduces both real-device failures.
</objective>
