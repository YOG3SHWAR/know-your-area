<objective>
Close the **single residual blocking gap** in `01-VERIFICATION.md` (the sibling of CR-01): `wrapOverlayLines` in `src/lib/overlay.ts` still **silently drops** the burned-in geotag/timestamp overlay when the formatted text needs **3+ physical lines** to wrap — e.g. a long/imprecise GPS accuracy value like `±123457m` (realistic for poor/indoor/urban-canyon fixes, and explicitly anticipated by `formatOverlayText`'s own test suite). Plan 01-08 genuinely fixed the original 2-line trigger (independently re-verified three ways); this round fixes the **second trigger in the same function** that reproduces the identical **D-02** anti-fraud failure mode via a different, equally realistic input.

Independently reproduced against the exact current source this planning pass:
`wrapOverlayLines(stubCtx, "12.9716, 77.5946 · ±123457m · 23 Jul 2026, 14:03", 20)` → `["12.9716, 77.5946 ·", "±123457m · 23 Jul"]` — the timestamp `2026, 14:03` vanishes with **no ellipsis, no signal**. The root cause: when the loop's `break` fires at the `lines.length >= OVERLAY_MAX_LINES` guard, the dangling word in `current` is appended by `if (current) lines.push(current)` and then chopped off by `lines.length = OVERLAY_MAX_LINES` — bypassing the ellipsis branch, which today only runs when the last line's own measured width overflows `maxWidth`. Any words after that fragment are already unreachable (the for-loop exited).

The burned-in overlay is this product's tamper-evident, "captured live, right here, right now" anti-fraud proof (CLAUDE.md Core Value; **D-02**, a Plan-level must-have from 01-03-PLAN.md). Silent timestamp loss is a genuine product-integrity defect, not cosmetic — so the fix must guarantee content is **never** dropped without a visible truncation signal.

Purpose: restore completeness of the burned-in overlay under the 3+-line trigger and lock it with a **content-based** (not length-only) regression test so this class cannot ship a third time.
Output: a corrected `wrapOverlayLines` whose break-truncation path never silently discards content, plus extended/new unit assertions checking the truncation signal.

**Scope discipline (per 01-VERIFICATION.md and the gap-closure scope):** This is a targeted single-defect fix. It does **NOT** touch any of `01-REVIEW.md`'s 10 Warning-level findings (WR-01..WR-10) or 6 Info-level findings (IN-01..IN-06) — all triaged non-blocking — nor the double-tap-race concurrency test, nor the 2 skipped real-device human-verification items (iOS Safari orientation/legibility, forced photo-404 placeholder). All 7 phase requirement IDs (SUBM-01/02/03/06, FEED-01/03/04) already show `✓ SATISFIED`; `requirements: [SUBM-01]` is cited only for traceability (the overlay is an artifact of the SUBM-01 live-capture flow under which D-02 was decided). The true driver is the **D-02** Plan-level must-have.
</objective>
