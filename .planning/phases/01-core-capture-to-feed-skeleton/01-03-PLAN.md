## Phase Goal (user story)

**As a** resident who does not trust official civic-reporting channels, **I want to** capture a live geo-tagged photo of a local problem, tag its category, and publish it, **so that** anyone nearby can see photo-verified local issues in a proximity feed and open any report by its ID or permalink.

<objective>
Harden the tracer's capture slice into the real SUBM-01/02/03 experience: burn the geotag+timestamp overlay, make the canvas orientation-safe, implement the GPS wait-for-fix window with stored accuracy, hard-block on permission denial, and add the 5-category picker with server-side re-validation.

Purpose: The Plan 02 tracer proved the path works; this plan makes it correct and safe on real mobile devices (the actual riskiest mechanics per RESEARCH). It refines files the tracer created — it does not touch the feed slice (Plan 04), so both run in wave 3 in parallel.
Output: A production-quality capture flow satisfying SUBM-01, SUBM-02, SUBM-03 and their locked decisions D-01..D-04.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser camera/GPS permission → app | Denied/absent permission must hard-block, not degrade to a spoofable path |
| browser → submit Server Action | Category and coordinates re-cross into the DB; client is never trusted |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | category value | high | mitigate | Server re-validates category against the 5-value zod enum in submitComplaint; a bypassed client cannot inject a 6th category. |
| T-01-04 | Spoofing | GPS at submit | medium | mitigate | Live `watchPosition` best-fix only; EXIF never read; no-fix hard-blocks rather than submitting a fallback coordinate. Residual spoofing accepted for Phase 1 (Phase 4 VERIFY-02). |
