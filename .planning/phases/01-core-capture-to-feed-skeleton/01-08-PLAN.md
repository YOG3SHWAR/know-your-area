<objective>
Close **CR-01 (blocking gap, this run's re-verification)** at the code level: `wrapOverlayLines` in `src/lib/overlay.ts` has an off-by-one word-wrap break condition that silently discards every word after the second line *starts*, dropping the burned-in **timestamp** — the exact artifact D-02's geotag+timestamp overlay exists to guarantee. Independently reproduced during verification: input `"12.9716, 77.5946 · ±18m · 23 Jul 2026, 14:03"` at a width where the coordinate+accuracy prefix alone fills line 1 produces `["12.9716, 77.5946 · ±18m", "·"]` — the entire date/time is gone.

The overlay is this product's tamper-evident, "photo-verified" anti-fraud proof (CLAUDE.md Core Value; D-02, a Plan-level must-have from 01-03-PLAN.md: "the overlay is part of the stored image bytes"). Silently losing its timestamp half undermines the phase goal's "geo-tagged photo" framing. This is a correctness bug in shipped code (introduced in commit `b71bd81`, Plan 01-03), not new scope.

The bug shipped because `wrapOverlayLines`/`drawOverlay` have **zero test coverage** — `tests/unit/overlay.test.ts` only exercises the pure `formatOverlayText` string builder. This plan applies the one-line break-condition fix AND adds the missing unit coverage so the regression cannot silently return.

Purpose: restore the completeness of the burned-in overlay (timestamp preserved) and close the coverage gap that let CR-01 ship.
Output: a corrected, exported `wrapOverlayLines`, plus a `describe('wrapOverlayLines')` test block that regression-locks the timestamp-retention behaviour and re-proves the 2-line cap + ellipsis truncation.

**Scope note — this is a Plan-level must-have (D-02) defect, not a REQUIREMENTS.md failure.** All 7 phase requirement IDs (SUBM-01/02/03/06, FEED-01/03/04) remain SATISFIED by plans 01-01…01-07 (the authoritative GPS location is stored server-side in the DB, independent of the image overlay). `requirements: [SUBM-01]` is cited only because the overlay is an artifact of the live-capture flow that SUBM-01 governs and D-02 was decided under; the true driver is the D-02 must-have. Explicitly out of scope (per 01-VERIFICATION.md): the 2 skipped real-device UAT items, the double-tap Publish race (`behavior_unverified_items`), and the 6 Warning-level code-review robustness gaps.
</objective>
