<objective>
Close the two remaining code gaps in `01-VERIFICATION.md` by fixing the *pattern* behind them, not by adding a fifth point-fix.

Gap 1 (blocker — CR-01 in `01-REVIEW.md`, VERIFICATION truth 21): `submitComplaint` rethrows any non-unique-violation DB/driver error verbatim across the Server Action boundary, and `capture/page.tsx` renders whatever it threw. This plan introduces ONE shared sanitization mechanism (`src/lib/sanitize-error.ts`), applies it to the publish path (closing gap 1), and retrofits the three prior ad-hoc sites onto it so the codebase has exactly one implementation instead of four.

Gap 2 (blocker — WR-08, VERIFICATION truth 22): the permalink page `/c/[id]` has no photo-404 fallback, unlike `FeedCard`'s existing `imgError` → category-tile pattern. This is an unrelated missing-fallback gap and stays a normal point-fix reusing the existing pattern.

Out of scope (already tracked in `01-VERIFICATION.md` as human-only, correctly deferred to end-of-phase UAT): the R2 bucket CORS dashboard change and the iOS Safari real-device orientation check. This plan does not touch those.

Purpose: eliminate the recurring raw-error-leak class at its root (one mechanism, four+ call sites) and give the shareable permalink the same graceful photo-404 degradation the feed already has.
Output: a shared `sanitizeError` utility consumed by all UI-facing catch sites, a sanitized + tested publish path, a permalink photo-404 fallback, and unit + e2e coverage for both.
